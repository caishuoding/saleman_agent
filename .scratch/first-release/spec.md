# 销售陪练首版实现

实现依据为本次讨论、docs/handoff.md 与根目录 sales-ui-prototype.html，使用原型选定的侧栏工作台。前后端分离，本地免登录，Python、LangGraph、PostgreSQL、DeepSeek Flash，前端采用 React、TypeScript、Vite，接口采用 FastAPI。

## 功能

- 三个训练入口先选产品，再由客户 Agent 生成并保存初始情境，点击开始确定开始时间。
- 客户 Agent 和教练 Agent 使用两个独立 LangGraph 图。教练贯穿练习指导、结束生成四部分复盘和复盘追问，延续同场教练历史。
- 客户与教练流式回复。结束后以教练当前上下文直接生成复盘，采用通用压缩机制。
- 每次调用统计完整输入 token，按扣除输出预留和安全余量后的 75% 触发增量摘要。压缩后保留最近六个完整轮次，窗口原文目标 12,000 token。新消息继续追加直到下次触发。
- 固定提示词、客户初始情境、产品资料、复盘保持独立。客户图和教练图各自维护摘要与覆盖序号，教练分别维护客户参考记录和自身问答摘要。
- 摘要保留说话人、数值、承诺、确认状态、更正和待办。压缩调用自身按预算分批。校验后原子提交摘要和覆盖位置，完整原文始终保存。
- 历史记录、收藏、重命名、状态/类型/产品组合筛选。首页最近未完成记录按开始时间选择。
- 续练恢复同场记录和开始时间。重练复制原初始情境、创建新记录和时间。
- 客户隐藏设定仅供客户使用。首访客户不预读产品资料，商务专项已知方案但未知报价。
- API 密钥保存在后端环境变量。错误可见、失败可重试、请求幂等、同场状态变更串行协调。

## 已确认测试入口

用户已同意通过公开 HTTP 接口测试开练、聊天、压缩、复盘、续练、重练，并通过浏览器验证 UI。模型 HTTP 接口在测试中用确定性服务替代，数据库采用实际 PostgreSQL。

## 验收

从 UI 正常入口完成选择、准备、开练、客户对话、教练提问、结束复盘、复盘追问、历史恢复、收藏、重命名与重练。压缩通过公开 API 验证消息连续性、独立状态、失败恢复。运行后端检查、前端类型检查与构建、完整测试，并执行 Standards/Spec 双轴代码审查，修复问题后提交。
