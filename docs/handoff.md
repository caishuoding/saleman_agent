## 已确认的产品范围

使用者是销售学员。学员推销产品，AI 扮演采购方的具体负责人，职务随业务情境确定。

第一版采用电脑浏览器文字交互，本地运行，免登录。语音、账号体系和团队培训管理安排在后续讨论。

### 首页与练习入口

- 首页有“需求沟通与方案介绍”“商务谈判与合作推进”两个专项，以及“完整流程练习”。
- 学员先进入具体练习入口，再选择本次推销的产品。
- 各专项使用独立对话与记忆。完整流程在同一场练习内持续推进各环节。
- 首页显示按开始时间最近的一次未完成练习，范围包括专项和完整流程。
- 主导航包含独立的“项目资料”入口，供学员学习和查阅多个产品的介绍书。练习中也能查看当前产品资料。

### 教练与复盘界面

- 练习中，学员点击“问教练”展开右侧教练对话。
- 学员点击“结束练习”，确认后结束客户沟通并进入复盘。
- 复盘采用三栏布局，左侧原始聊天记录，中间复盘总结，右侧可提问的教练助手。
- 教练应能结合客户聊天记录和复盘总结回答关于本次练习的问题。
- 复盘总结的具体内容、评价维度与生成实现仍待讨论。逐字引用及点击定位原文的功能已由用户取消。

### 历史记录与收藏

- 两处均展示练习名称、产品、练习类型、开始时间与完成状态。
- 两处均支持重命名，并支持按已完成或未完成、专项分类及产品组合筛选。
- 列表省略甲方公司和姓名。
- 学员可收藏单次练习，并从独立收藏入口查看。
- 收藏中的删除操作经确认后移除收藏关联，原历史记录继续可查看。
- 续练恢复原记录并沿用开始时间。重练创建新记录和新的开始时间。

## AI 客户的最新决定

### 公司背景与需求

用户最终决定让模型自行构建甲方背景和具体需求。此前人工编写的三套详细甲方案例已按用户要求删除。

已删除的资料共七份，包括 `data/cases/` 下的三份案例及目录说明，以及 `docs/research/` 下三个 `*-buyer-case-references.md`。空案例目录也已清理。

三个产品介绍书继续作为学员的推销资料使用。原型中的远川科技、明川咨询、启恒制造及其联系人属于既有界面演示内容。详细案例文件删除后，原型仍保留这些演示文本。

### 提示词与认知起点

AI 客户通过系统提示词维持甲方身份和通用角色规则，结合当前练习类型构建业务情境，并保持本次练习中已表达事实的一致性。

| 练习类型 | 甲方起始认知 |
| --- | --- |
| 需求沟通与方案介绍 | 了解自身业务和问题，从首次沟通开始，通过学员介绍了解卖方产品。用户认为这一阶段甲方无需预读产品资料 |
| 商务谈判与合作推进 | 已了解产品功能或初步方案，尚未收到报价。报价通过本次与学员的沟通获得 |
| 完整流程练习 | 从首次接触开始，在同一场练习内逐渐了解功能、报价和合作安排 |

各专项的起点独立准备。完整流程沿用本场对话中的认知和约定。

此前讨论过的客户行为包括根据学员提问自然说明业务、回应方案适用性、讨论费用及采购安排，并按自身职责推进下一步。开放问题可以获得连贯的背景说明。客户系统提示词的讨论保存在此前聊天中，项目文件中尚无独立的正式提示词文件。

模型自行构建背景的具体生成时机、保存结构，以及重练时如何恢复该背景，仍需在工程落实时与既有续练和重练要求对齐。

## 教练当前讨论进度

目前提出的实现思路如下，接下来可围绕这些内容继续讨论。

1. 客户和教练使用同一个模型，各自维护独立的系统提示词及消息上下文。
2. 每次学员向教练提问，后端读取当前练习类型、产品介绍书、客户聊天记录以及本次教练交流，再组装模型输入。
3. 复盘阶段额外加入已经生成的复盘总结。
4. 在 LangGraph 中通过教练节点处理请求，模型回复流式显示到右侧教练栏。
5. 教练交流保存在 PostgreSQL，关联当前练习，续练时恢复。

当前资料规模下，上一轮建议直接把产品介绍书放入教练上下文。知识检索架构、上下文压缩及工具调用尚未展开讨论。

上一轮概括的请求流程为“学员提问 → 读取资料和记录 → 组装上下文 → 模型回复 → 保存交流记录”。

教练系统提示词的正式文本、练习中与复盘后的具体上下文衔接，以及复盘总结如何生成，可以作为后续讨论内容。用户当前授权范围是讨论方案。
