# 实时语音陪练架构调研

核查日期为 2026-11-13。本文结合官方文档和当前代码讨论架构，供应商尚待选择。本文覆盖接口与设计依据，语音质量、网络延迟及真实打断效果需要接入后验证。现有选型资料见 [中文销售陪练语音模型选型调研](voice-model-selection-2026-11-12.md)。

## 当前项目

- 训练范围包含需求沟通与方案介绍、商务谈判与合作推进，以及完整练习。客户记忆按单次练习隔离，练习中可向训练教练求助，结束后进入复盘。语音属于后续迭代范围。[产品范围](../product-scope.md)
- 双入口和语音预览界面已有本地规格，通话与语音教练当前标记为待接入。[语音入口规格](../../.scratch/voice-entry-ui/spec.md)
- 客户和教练分别编译 LangGraph，当前图为输入检查、按需摘要压缩、回复生成。模型正文通过 `get_stream_writer()` 自定义事件输出，图本身通过 `compile(name=name)` 编译，当前尚未配置工具循环或 checkpointer。[当前 Agent 实现](../../backend/agents.py)
- 文本上下文包含固定资料、分来源历史、增量摘要和本轮输入。摘要已经区分事实、方案、约定、待解决问题、更正及教练建议，这些业务概念可沿用到语音记录与续练恢复。[当前记忆实现](../../backend/memory.py)
- `Exchange` 按完整问答保存 `input` 和 `output`，`generate()` 在生成整轮时持有练习 advisory lock。语音事件持久化和长连接的并发控制需要适配。[当前数据模型](../../backend/db.py) [当前生成接口](../../backend/app.py)

## 官方接口事实

### 实时语音仍有上下文和工具循环

以 OpenAI Realtime 为例，连接后持续维护 Session、Conversation 和 Responses。应用可以更新 `instructions`、补充对话项并处理服务端事件。同一场会话的输入输出可以逐步累积，应用仍需决定角色背景、持久化内容和续练恢复策略。[Realtime 会话管理](https://developers.openai.com/api/docs/guides/realtime-conversations)

函数工具需要注册。模型产生函数调用后，应用执行代码，返回关联 `call_id` 的 `function_call_output`，随后可用 `response.create` 继续生成。需要由后端完成的查资料、数据库访问和业务操作仍由应用负责。[Realtime 工具文档](https://developers.openai.com/api/docs/guides/realtime-mcp)

### 浏览器可以使用 WebRTC

OpenAI Realtime 支持浏览器 WebRTC。音频通过媒体连接传输，控制事件通过 data channel 传输。会话可由后端交换 SDP 建立，也可以向浏览器发放临时凭证。标准 API Key 保存在服务端。[WebRTC 接入](https://developers.openai.com/api/docs/guides/voice-webrtc?api=realtime)

后端可以建立 sideband WebSocket 控制同一通话，监听事件、更新指令和执行私有工具。具体端点及事件需要与所选 API 对应。[服务端控制](https://developers.openai.com/api/docs/guides/voice-server-controls?api=realtime&voice-api=realtime)

### 判停和打断需要应用状态配合

VAD 可以报告用户开始和停止说话。OpenAI Realtime 提供基于静音的 `server_vad` 和结合表达完整度的 `semantic_vad`，并允许配置自动回复与自动打断。实际使用需调节噪声阈值、停顿时间和抢话倾向。[VAD 文档](https://developers.openai.com/api/docs/guides/realtime-vad)

打断涉及停止播放、清空待播音频和同步模型上下文。在 OpenAI Realtime 的 WebSocket 接法中，客户端需记录播放毫秒数，并发送 `conversation.item.truncate`。WebRTC 的未播音频截断由服务端管理。官方说明截断接口无法提供精确对齐后的截断文字稿，因此记录模型生成全文时还应保留打断标记与播放位置。[打断与截断](https://developers.openai.com/api/docs/guides/realtime-conversations#interruption-and-truncation)

### LangGraph 可以接入原生流式接口

LangGraph 的 `stream()` 和 `astream()` 能输出图状态、模型 token 和自定义数据。`custom` 模式允许节点使用原生客户端接入外部流式 API，适配器可以把实时服务的业务结果交给图处理。[LangGraph 流式文档](https://docs.langchain.com/oss/python/langgraph/streaming)

LangGraph 的 Pregel 运行时按 superstep 调度节点，在步骤完成后更新通道状态。这为业务状态转移提供了执行模型，具体媒体传输、音频缓冲和播放控制由应用选择实现。[LangGraph 运行时](https://docs.langchain.com/oss/python/langgraph/pregel)

LangGraph 的 `interrupt()` 用于暂停图、保存检查点并等待外部输入。语音插话还需由语音会话及播放器处理。图检查点保存的是图状态，续练需要的业务记录和实时会话恢复资料应按应用设计持久化。[LangGraph 中断](https://docs.langchain.com/oss/python/langgraph/interrupts) [LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence)

### 语音架构可以有不同分工

官方当前区分原生语音会话、识别到文本 Agent 再到语音合成的级联流程，以及 GPT-Live 语音前端委托独立后端的架构。独立后端委托允许保留自有工作流和后端模型。模型对这些能力的支持应逐个确认。[语音 Agent 架构](https://developers.openai.com/api/docs/guides/voice-agents)

## 结合当前项目的设计建议

本节属于工程建议，具体接口根据后续供应商选型确定。

### 业务模型

每个专项提供文字与语音入口。训练类型继续表示练习内容，交互模式独立记录为文字或语音。创建练习时固定交互模式，案例、产品快照、练习状态、收藏和复盘沿用现有业务关系。每场练习拥有独立的模拟客户上下文。

### 组件职责

- 浏览器处理麦克风、音频播放、静音、设备权限、连接状态和临时字幕。播放进度与打断信息进入持久化事件。
- 实时会话服务维护供应商连接、初始化客户角色和专项范围、翻译供应商事件、调度工具调用，并保存最终转写与响应状态。
- LangGraph 继续处理业务工作流，包括训练教练、复盘，以及需要多步骤执行的工具任务。原生语音模型扮演客户时，媒体收发由实时服务持续运行。
- PostgreSQL 保存业务事实和训练记录，作为续练、教练与复盘的读取来源。

将音频持续收发放在独立事件循环，并以完整转写、工具调用和练习结束等事件触发业务处理，适合当前图的职责。节点中也可以管理实时连接，具体选择取决于取消、恢复和并发复杂度。每个音频分片都进入业务图会增加状态更新与持久化负担。语音连接期间数据库操作使用短事务，并在短暂的业务状态变更上处理并发，保持教练和结束练习等操作可执行。

### 上下文与记录

可以沿用 `customer_prompt()` 中采购方身份、产品资料权限、专项边界和案例背景，另加语音表达要求，例如回答简短自然、一次只问一个问题、金额不清时先确认。语音模型与 DeepSeek 的指令服从表现需要分别验证。

建议维护三类状态。

1. 实时服务内的会话上下文，支持当前连续对话。
2. 应用内的客户事实、学员方案、双方约定和更正，支持续练和资料一致性。
3. 带说话人、时间、最终转写、响应状态、供应商 item ID 和播放位置的对话事件，支持字幕、教练与复盘。

建议为语音新增按发言或事件保存的记录结构，容纳连续插话和响应被取消等状态。临时转写可持续更新，完成后再确认为训练记录。用户转写完成事件可能晚于模型开始回复，事件应按 item ID 和轮次关系整理，避免只凭到达顺序拼接。模型生成全文、已发送音频和实际播放内容应保留各自状态。精确逐字恢复已播放文字取决于供应商提供的对齐能力，缺少对齐时可保存原文并标记被打断，复盘排除未确认播放部分。

断线或续练时，从数据库取案例、固定指令、已确认事实摘要和近期有效对话来恢复实时会话。会话连接 ID 与业务练习 ID 分开记录，具体恢复机制遵循所选供应商文档。客户上下文中仅包含客户可知信息，训练教练的私密建议保存在独立对话中。

### 工具与取消

实时事件循环收到函数调用后，将完整参数交给后端工具或 LangGraph 子流程，按原调用 ID 返回结构化结果。耗时任务由独立异步任务执行，接收新语音与停止播放保持响应。工具调用按调用 ID 去重，可重试操作提供幂等语义，结果与所属练习和会话版本关联。

学员插话、结束练习或重新连接后，旧任务结果仍可能返回。结果回传前检查所属会话、任务状态及是否仍有回应需求，避免旧结果触发过期播报。取消音频生成与取消业务操作分别记录，已完成操作保持真实状态。

训练教练可先沿用文字求助入口。学员打开教练并交流时，建议暂停客户采音和自动回应，返回客户后继续。结束练习时停止录音与播报，在限定等待时间内收集最终事件，对缺失或未完成部分明确标记，再将有效记录交给既有复盘流程。

## 首轮验证范围

先选择一个专项、一种实时供应商接通创建会话、持续对话、自然判停、插话、最终转写落库、结束与复盘。随后验证续练、长对话摘要与工具调用。

使用相同销售案例，至少覆盖学员句中停顿、附和声、客户播报中被打断、金额和产品术语、断线恢复、打开教练、结束时仍在生成，以及旧工具结果迟到。记录学员说完到首段可听回复的时延、插话到停播的时延、专项越界、事实一致性、记录完整度和整场费用。上述范围服务于接入验收，供应商选择由真实测试结果确定。
